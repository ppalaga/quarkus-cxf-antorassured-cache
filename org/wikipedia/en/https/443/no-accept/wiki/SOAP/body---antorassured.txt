<p id="mwCg"><b id="mwCw">SOAP</b> (originally an acronym for <b id="mwDA">Simple Object Access Protocol</b>)<sup about="#mwt13" class="mw-ref reference" id="cite_ref-1" rel="dc:references" typeof="mw:Transclusion mw:Extension/ref" data-mw='{"name":"ref","attrs":{"group":"lower-alpha"},"body":{"id":"mw-reference-text-cite_note-1"},"parts":[{"template":{"target":{"wt":"efn","href":"./Template:Efn"},"params":{"1":{"wt":"Since version 1.2 of the specification it is no longer an [[acronym]] for Simple Object Access Protocol"}},"i":0}}]}'><a href="#cite_note-1" data-mw-group="lower-alpha" id="mwDQ"><span class="mw-reflink-text" id="mwDg"><span class="cite-bracket" id="mwDw">[</span>a<span class="cite-bracket" id="mwEA">]</span></span></a></sup> is a messaging <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Protocol_(computing)" title="Protocol (computing)" class="mw-redirect" id="mwEQ">protocol</a> specification for exchanging structured information in the implementation of <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Web_service" title="Web service" id="mwEg">web services</a> in <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Computer_network" title="Computer network" id="mwEw">computer networks</a>. It uses <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/XML_Information_Set" title="XML Information Set" id="mwFA">XML Information Set</a> for its <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Message_format" title="Message format" id="mwFQ">message format</a>, and relies on <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Application_layer" title="Application layer" id="mwFg">application layer</a> protocols, most often <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Hypertext_Transfer_Protocol" title="Hypertext Transfer Protocol" class="mw-redirect" id="mwFw">Hypertext Transfer Protocol</a> (HTTP), although some legacy systems communicate over <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Simple_Mail_Transfer_Protocol" title="Simple Mail Transfer Protocol" id="mwGA">Simple Mail Transfer Protocol</a> (SMTP), for message negotiation and transmission.</p>

<meta property="mw:PageProp/toc" id="mwGQ" data-mw='{"autoGenerated":true}'/></section><section data-mw-section-id="1" id="mwGg" aria-labelledby="Characteristics"><div class="mw-heading mw-heading2"><h2 id="Characteristics">Characteristics</h2><span class="mw-editsection"><span class="mw-editsection-bracket">[</span><a href="/w/index.php?title=SOAP&amp;action=edit&amp;section=1" title="Edit section: Characteristics"><span>edit</span></a><span class="mw-editsection-bracket">]</span></span></div>
<p id="mwGw">SOAP provides the Messaging Protocol layer of a <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Web_services_protocol_stack" title="Web services protocol stack" id="mwHA">web services protocol stack</a> for web services. It is an XML-based protocol consisting of three parts: </p>
<ul id="mwHQ"><li id="mwHg">an envelope, which defines the message structure<sup about="#mwt19" class="mw-ref reference" id="cite_ref-2" rel="dc:references" typeof="mw:Extension/ref" data-mw='{"name":"ref","attrs":{},"body":{"id":"mw-reference-text-cite_note-2"}}'><a href="#cite_note-2" id="mwHw"><span class="mw-reflink-text" id="mwIA"><span class="cite-bracket" id="mwIQ">[</span>1<span class="cite-bracket" id="mwIg">]</span></span></a></sup> and how to process it</li>
<li id="mwIw">a set of encoding rules for expressing instances of application-defined datatypes</li>
<li id="mwJA">a convention for representing procedure calls and responses</li></ul>

<p id="mwJQ">SOAP has three major characteristics:</p>

<ol id="mwJg"><li id="mwJw"><i id="mwKA">extensibility</i> (security and <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/WS-Addressing" title="WS-Addressing" id="mwKQ">WS-Addressing</a> are among the extensions under development)</li>
<li id="mwKg"><i id="mwKw">neutrality</i> (SOAP can operate over any protocol such as <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/HTTP" title="HTTP" id="mwLA">HTTP</a>, <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/SMTP" title="SMTP" class="mw-redirect" id="mwLQ">SMTP</a>, <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Transmission_Control_Protocol" title="Transmission Control Protocol" id="mwLg">TCP</a>, <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/SOAP-over-UDP" title="SOAP-over-UDP" id="mwLw">UDP</a>)</li>
<li id="mwMA"><i id="mwMQ">independence</i> (SOAP allows for any <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Programming_model" title="Programming model" id="mwMg">programming model</a>)</li></ol>

<p id="mwMw">As an example of what SOAP procedures can do, an application can send a SOAP request to a server that has web services enabled—such as a real-estate price database—with the parameters for a search. The server then returns a SOAP response (an XML-formatted document) with the resulting data, e.g., prices, location, features. Since the generated data comes in a standardized machine-parsable format, the requesting application can then integrate it directly.</p>

<p id="mwNA">The SOAP architecture consists of several layers of specifications for:</p>

<ul id="mwNQ"><li id="mwNg">message format</li>
<li id="mwNw"><a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Message_Exchange_Pattern" title="Message Exchange Pattern" class="mw-redirect" id="mwOA">Message Exchange Patterns</a> (MEP)</li>
<li id="mwOQ">underlying transport protocol bindings</li>
<li id="mwOg">message processing models</li>
<li id="mwOw">protocol extensibility</li></ul>

<p id="mwPA">SOAP evolved as a successor of <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/XML-RPC" title="XML-RPC" id="mwPQ">XML-RPC</a>, though it borrows its transport and interaction neutrality from Web Service Addressing<sup about="#mwt23" class="mw-ref reference" id="cite_ref-3" rel="dc:references" typeof="mw:Extension/ref" data-mw='{"name":"ref","attrs":{},"body":{"id":"mw-reference-text-cite_note-3"}}'><a href="#cite_note-3" id="mwPg"><span class="mw-reflink-text" id="mwPw"><span class="cite-bracket" id="mwQA">[</span>2<span class="cite-bracket" id="mwQQ">]</span></span></a></sup> and the envelope/header/body from elsewhere (probably from <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/WDDX" title="WDDX" id="mwQg">WDDX</a>).<link rel="mw:PageProp/Category" href="./Category:All_articles_with_unsourced_statements" about="#mwt20" typeof="mw:Transclusion" id="mwQw" data-mw='{"parts":[{"template":{"target":{"wt":"Citation needed","href":"./Template:Citation_needed"},"params":{"date":{"wt":"August 2011"}},"i":0}}]}'/><link rel="mw:PageProp/Category" href="./Category:Articles_with_unsourced_statements_from_August_2011" about="#mwt20"/><sup class="noprint Inline-Template Template-Fact" style="white-space:nowrap;" about="#mwt20" id="mwRA"><span typeof="mw:Entity">[</span><i><a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Wikipedia:Citation_needed" title="Wikipedia:Citation needed"><span title="This claim needs references to reliable sources. (August 2011)">citation needed</span></a></i><span typeof="mw:Entity">]</span></sup></p>

</section><section data-mw-section-id="2" id="mwRQ" aria-labelledby="History"><div class="mw-heading mw-heading2"><h2 id="History">History</h2><span class="mw-editsection"><span class="mw-editsection-bracket">[</span><a href="/w/index.php?title=SOAP&amp;action=edit&amp;section=2" title="Edit section: History"><span>edit</span></a><span class="mw-editsection-bracket">]</span></span></div>
<p id="mwRg">SOAP was designed as an object-access protocol and released as <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/XML-RPC" title="XML-RPC" id="mwRw">XML-RPC</a> in June 1998 as part of <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/UserLand_Software" title="UserLand Software" id="mwSA">Frontier</a> 5.1 by <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Dave_Winer" title="Dave Winer" id="mwSQ">Dave Winer</a>, <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Don_Box" title="Don Box" id="mwSg">Don Box</a>, Bob Atkinson, and Mohsen Al-Ghosein for <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Microsoft" title="Microsoft" id="mwSw">Microsoft</a>, where Atkinson and Al-Ghosein were working.<sup about="#mwt26" class="mw-ref reference" id="cite_ref-4" rel="dc:references" typeof="mw:Extension/ref" data-mw='{"name":"ref","attrs":{},"body":{"id":"mw-reference-text-cite_note-4"}}'><a href="#cite_note-4" id="mwTA"><span class="mw-reflink-text" id="mwTQ"><span class="cite-bracket" id="mwTg">[</span>3<span class="cite-bracket" id="mwTw">]</span></span></a></sup>  The specification was not made available until it was submitted to <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/IETF" title="IETF" class="mw-redirect" id="mwUA">IETF</a> 13 September 1999.<sup about="#mwt29" class="mw-ref reference" id="cite_ref-5" rel="dc:references" typeof="mw:Extension/ref" data-mw='{"name":"ref","attrs":{},"body":{"id":"mw-reference-text-cite_note-5"}}'><a href="#cite_note-5" id="mwUQ"><span class="mw-reflink-text" id="mwUg"><span class="cite-bracket" id="mwUw">[</span>4<span class="cite-bracket" id="mwVA">]</span></span></a></sup><sup about="#mwt32" class="mw-ref reference" id="cite_ref-6" rel="dc:references" typeof="mw:Extension/ref" data-mw='{"name":"ref","attrs":{},"body":{"id":"mw-reference-text-cite_note-6"}}'><a href="#cite_note-6" id="mwVQ"><span class="mw-reflink-text" id="mwVg"><span class="cite-bracket" id="mwVw">[</span>5<span class="cite-bracket" id="mwWA">]</span></span></a></sup> According to Don Box, this was due to politics within Microsoft.<sup about="#mwt35" class="mw-ref reference" id="cite_ref-7" rel="dc:references" typeof="mw:Extension/ref" data-mw='{"name":"ref","attrs":{},"body":{"id":"mw-reference-text-cite_note-7"}}'><a href="#cite_note-7" id="mwWQ"><span class="mw-reflink-text" id="mwWg"><span class="cite-bracket" data-mw='{"name":"ref","attrs":{},"body":{"id":"mw-reference-text-cite_note-8"}}'><a href="#cite_note-8" id="mwXg"><span class="mw-reflink-text" id="mwXw"><span class="cite-bracket" id="mwYA">[</span>7<span class="cite-bracket" id="mwYQ">]</span></span></a></sup></p>

<p id="mwYg">The submitted <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Internet_Draft" title="Internet Draft" id="mwYw">Internet Draft</a> did not reach <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Request_for_Comments" title="Request for Comments" id="mwZA">RFC</a> status and is therefore not considered a "web standard" as such. Version 1.1 of the specification was published as a W3C Note on 8 May 2000.<sup about="#mwt41" class="mw-ref reference" id="cite_ref-9" rel="dc:references" typeof="mw:Extension/ref" data-mw='{"name":"ref","attrs":{},"body":{"id":"mw-reference-text-cite_note-9"}}'><a href="#cite_note-9" id="mwZQ"><span class="mw-reflink-text" id="mwZg"><span class="cite-bracket" id="mwZw">[</span>8<span class="cite-bracket" id="mwaA">]</span></span></a></sup> Since version 1.1 did not reach <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/W3C_Recommendation" title="W3C Recommendation" class="mw-redirect" id="mwaQ">W3C Recommendation</a> status, it can not be considered a "web standard" either. Version 1.2 of the specification, however, became a <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/World_Wide_Web_Consortium" title="World Wide Web Consortium" id="mwag">W3C</a> recommendation on June 24, 2003. <i id="mwaw">SOAP</i> originally stood for "Simple Object Access Protocol" but version 1.2 of the standard dropped this acronym.<sup about="#mwt44" class="mw-ref reference" id="cite_ref-10" rel="dc:references" typeof="mw:Extension/ref" data-mw='{"name":"ref","attrs":{},"body":{"id":"mw-reference-text-cite_note-10"}}'><a href="#cite_note-10" id="mwbA"><span class="mw-reflink-text" id="mwbQ"><span class="cite-bracket" id="mwbg">[</span>9<span class="cite-bracket" id="mwbw">]</span></span></a></sup></p>

<p id="mwcA">The SOAP specification<sup about="#mwt47" class="mw-ref reference" id="cite_ref-11" rel="dc:references" typeof="mw:Extension/ref" data-mw='{"name":"ref","attrs":{},"body":{"id":"mw-reference-text-cite_note-11"}}'><a href="#cite_note-11" id="mwcQ"><span class="mw-reflink-text" id="mwcg"><span class="cite-bracket" id="mwcw">[</span>10<span class="cite-bracket" id="mwdA">]</span></span></a></sup> was  maintained by the XML Protocol Working Group<sup about="#mwt50" class="mw-ref reference" id="cite_ref-12" rel="dc:references" typeof="mw:Extension/ref" data-mw='{"name":"ref","attrs":{},"body":{"id":"mw-reference-text-cite_note-12"}}'><a href="#cite_note-12" id="mwdQ"><span class="mw-reflink-text" id="mwdg"><span class="cite-bracket" id="mwdw">[</span>11<span class="cite-bracket" id="mweA">]</span></span></a></sup> of the <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/World_Wide_Web_Consortium" title="World Wide Web Consortium" id="mweQ">World Wide Web Consortium</a> until the group was closed 10 July 2009. </p>

<p id="mweg">After SOAP was first introduced, it became the underlying layer of a more complex set of <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Web_service" title="Web service" id="mwew">web services</a>, based on <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Web_Services_Description_Language" title="Web Services Description Language" id="mwfA">WSDL</a>, <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/XML_Schema_(W3C)" title="XML Schema (W3C)" id="mwfQ">XSD</a> and <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Universal_Description_Discovery_and_Integration" title="Universal Description Discovery and Integration" class="mw-redirect" id="mwfg">UDDI</a>. These different services, especially UDDI, have proved to be of far less interest,<link rel="mw:PageProp/Category" href="./Category:All_articles_with_unsourced_statements" about="#mwt51" typeof="mw:Transclusion" id="mwfw" data-mw='{"parts":[{"template":{"target":{"wt":"citation needed","href":"./Template:Citation_needed"},"params":{"date":{"wt":"March 2025"}},"i":0}}]}'/><link rel="mw:PageProp/Category" href="./Category:Articles_with_unsourced_statements_from_March_2025" about="#mwt51"/><sup class="noprint Inline-Template Template-Fact" style="white-space:nowrap;" about="#mwt51" id="mwgA"><span typeof="mw:Entity">[</span><i><a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Wikipedia:Citation_needed" title="Wikipedia:Citation needed"><span title="This claim needs references to reliable sources. </section><section data-mw-section-id="3" id="mwgw" aria-labelledby="SOAP_terminology"><div class="mw-heading mw-heading2"><h2 id="SOAP_terminology">SOAP terminology</h2><span class="mw-editsection"><span class="mw-editsection-bracket">[</span><a href="/w/index.php?title=SOAP&amp;action=edit&amp;section=3" title="Edit section: SOAP terminology"><span>edit</span></a><span class="mw-editsection-bracket">]</span></span></div>
<p id="mwhA">SOAP specification can be broadly defined to be consisting of the following three conceptual components: protocol concepts, encapsulation concepts and network concepts.<sup about="#mwt55" class="mw-ref reference" id="cite_ref-13" rel="dc:references" typeof="mw:Extension/ref" data-mw='{"name":"ref","attrs":{},"body":{"id":"mw-reference-text-cite_note-13"}}'><a href="#cite_note-13" id="mwhQ"><span class="mw-reflink-text" id="mwhg"><span class="cite-bracket" id="mwhw">[</span>12<span class="cite-bracket" id="mwiA">]</span></span></a></sup></p>

<section data-mw-section-id="4" id="mwiQ" aria-labelledby="Protocol_concepts"><div class="mw-heading mw-heading3"><h3 id="Protocol_concepts">Protocol concepts</h3><span class="mw-editsection"><span class="mw-editsection-bracket">[</span><a href="/w/index.php?title=SOAP&amp;action=edit&amp;section=4" title="Edit section: Protocol concepts"><span>edit</span></a><span class="mw-editsection-bracket">]</span></span></div>
<dl id="mwig"><dt id="mwiw">SOAP</dt><dd id="mwjA">This is a set of rules formalizing and governing the format and processing rules for information exchanged between a SOAP sender and a SOAP receiver.</dd>
<dt id="mwjQ">SOAP nodes</dt><dd id="mwjg">These are physical/logical machines with processing units which are used to transmit/forward, receive and process SOAP messages. These are analogous to <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Node_(networking)" title="Node (networking)" class="mw-redirect" id="mwjw">nodes</a> in a network.</dd>
<dt id="mwkA">SOAP roles</dt><dd id="mwkQ">Over the path of a SOAP message, all nodes assume a specific role. The role of the node defines the action that the node performs on the message it receives. For example, a role "<i id="mwkg">none"</i> means that no node will process the SOAP header in any way and simply transmit the message along its path.</dd>
<dt id="mwkw">SOAP protocol binding</dt><dd id="mwlA">A SOAP message needs to work in conjunction with other protocols to be transferred over a network. For example, a SOAP message could use <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Transmission_Control_Protocol" title="Transmission Control Protocol" id="mwlQ">TCP</a> as a lower layer protocol to transfer messages. These bindings are defined in the SOAP protocol binding framework.<sup about="#mwt58" class="mw-ref reference" id="cite_ref-14" rel="dc:references" typeof="mw:Extension/ref" data-mw='{"name":"ref","attrs":{},"body":{"id":"mw-reference-text-cite_note-14"}}'><a href="#cite_note-14" id="mwlg"><span class="mw-reflink-text" id="mwlw"><span class="cite-bracket" id="mwmA">[</span>13<span class="cite-bracket" id="mwmQ">]</span></span></a></sup></dd>
<dt id="mwmg">SOAP features</dt><dd id="mwmw">SOAP provides a messaging framework only. However, it can be extended to add features such as reliability, security etc. There are rules to be followed when adding features to the SOAP framework.</dd>
<dt id="mwnA">SOAP module</dt><dd id="mwnQ">A collection of specifications regarding the semantics of SOAP header to describe any new features being extended upon SOAP. A module needs to realize zero or more features. SOAP requires modules to adhere to prescribed rules.<sup about="#mwt61" class="mw-ref reference" id="cite_ref-15" rel="dc:references" typeof="mw:Extension/ref" data-mw='{"name":"ref","attrs":{},"body":{"id":"mw-reference-text-cite_note-15"}}'><a href="#cite_note-15" id="mwng"><span class="mw-reflink-text" id="mwnw"><span class="cite-bracket" id="mwoA">[</span>14<span class="cite-bracket" id="mwoQ">]</span></span></a></sup></dd></dl>

</section><section data-mw-section-id="5" id="mwog" aria-labelledby="Data_encapsulation_concepts"><div class="mw-heading mw-heading3"><h3 id="Data_encapsulation_concepts">Data encapsulation concepts</h3><span class="mw-editsection"><span class="mw-editsection-bracket">[</span><a href="/w/index.php?title=SOAP&amp;action=edit&amp;section=5" title="Edit section: Data encapsulation concepts"><span>edit</span></a><span class="mw-editsection-bracket">]</span></span></div>
<dl id="mwow"><dt id="mwpA">SOAP message</dt><dd id="mwpQ">Represents the information being exchanged between 2 SOAP nodes.</dd>
<dt id="mwpg">SOAP envelope</dt><dd id="mwpw">It is the enclosing element of an XML message identifying it as a SOAP message.</dd>
<dt id="mwqA">SOAP header block</dt><dd id="mwqQ">A SOAP header can contain more than one of these blocks, each being a discrete computational block within the header. In general, the SOAP <i id="mwqg">role</i> information is used to target nodes on the path. A header block is said to be targeted at a SOAP node if the SOAP role for the header block is the name of a role in which the SOAP node operates. (ex: A SOAP header block with role attribute as <i id="mwqw">ultimateReceiver</i> is targeted only at the destination node which has this role. A header with a role attribute as <i id="mwrA">next</i> is targeted at each intermediary as well as the destination node.)</dd>
<dt id="mwrQ">SOAP header</dt><dd id="mwrg">A collection of one or more header blocks targeted at each SOAP receiver.</dd>
<dt id="mwrw">SOAP body</dt><dd id="mwsA">Contains the body of the message intended for the SOAP receiver. The interpretation and processing of SOAP body is defined by header blocks.</dd>
<dt id="mwsQ">SOAP fault</dt><dd id="mwsg">In case a SOAP node fails to process a SOAP message, it adds the fault information to the SOAP fault element. This element is contained within the SOAP body as a child element.</dd></dl>

</section><section data-mw-section-id="6" id="mwsw" aria-labelledby="Message_sender_and_receiver_concepts"><div class="mw-heading mw-heading3"><h3 id="Message_sender_and_receiver_concepts">Message sender and receiver concepts</h3><span class="mw-editsection"><span class="mw-editsection-bracket">[</span><a href="/w/index.php?title=SOAP&amp;action=edit&amp;section=6" title="Edit section: Message sender and receiver concepts"><span>edit</span></a><span class="mw-editsection-bracket">]</span></span></div>
<dl id="mwtA"><dt id="mwtQ">SOAP sender</dt><dd id="mwtg">The node that transmits a SOAP message.</dd>
<dt id="mwtw">SOAP receiver</dt><dd id="mwuA">The node receiving a SOAP message. (Could be an intermediary or the destination node).</dd>
<dt id="mwuQ">SOAP message path</dt><dd id="mwug">The path consisting of all the nodes that the SOAP message traversed to reach the destination node.</dd>
<dt id="mwuw">Initial SOAP sender</dt><dd id="mwvA">This is the node which originated the SOAP message to be transmitted. This is the root of the SOAP message path.</dd>
<dt id="mwvQ">SOAP intermediary</dt><dd id="mwvg">All the nodes in between the SOAP originator and the intended SOAP destination. It processes the SOAP header blocks targeted at it and acts to forward a SOAP message towards an ultimate SOAP receiver.</dd>
<dt id="mwvw">Ultimate SOAP receiver</dt><dd id="mwwA">The destination receiver of the SOAP message. This node is responsible for processing the message body and any header blocks targeted at it.</dd></dl>

</section></section><section data-mw-section-id="7" id="mwwQ" aria-labelledby="Specification"><div class="mw-heading mw-heading2"><h2 id="Specification">Specification</h2><span class="mw-editsection"><span class="mw-editsection-bracket">[</span><a href="/w/index.php?title=SOAP&amp;action=edit&amp;section=7" title="Edit section: Specification"><span>edit</span></a><span class="mw-editsection-bracket">]</span></span></div>
<figure class="mw-default-size" typeof="mw:File/Thumb" id="mwwg"><a href="https://en.wikipedia.org/wiki/File:SOAP.svg" class="mw-file-description" id="mwww"><img resource="https://en.wikipedia.org/wiki/File:SOAP.svg" src="//thumb.wikimedia.org/wikipedia/commons/thumb/5/59/SOAP.svg/250px-SOAP.svg.png?utm_source=en.wikipedia.org&amp;utm_campaign=parser&amp;utm_content=thumbnail" decoding="async" loading="lazy" srcset="//thumb.wikimedia.org/wikipedia/commons/thumb/5/59/SOAP.svg/500px-SOAP.svg.png?utm_source=en.wikipedia.org&amp;utm_campaign=parser&amp;utm_content=thumbnail 2x" data-file-width="182" data-file-height="194" data-file-type="drawing" height="266" width="250" class="mw-file-element" id="mwxA"/></a><figcaption id="mwxQ">SOAP structure</figcaption></figure>

<p id="mwxg">The SOAP specification defines the messaging framework, which consists of:</p>
<ul id="mwxw"><li id="mwyA">The <i id="mwyQ">SOAP processing model</i>, defining the rules for processing a SOAP message<sup about="#mwt64" class="mw-ref reference" id="cite_ref-auto_16-0" rel="dc:references" typeof="mw:Extension/ref" data-mw='{"name":"ref","attrs":{"name":"auto"},"body":{"id":"mw-reference-text-cite_note-auto-16"}}'><a href="#cite_note-auto-16" id="mwyg"><span class="mw-reflink-text" id="mwyw"><span class="cite-bracket" id="mwzA">[</span>15<span class="cite-bracket" id="mwzQ">]</span></span></a></sup></li>
<li id="mwzg">The <i id="mwzw">SOAP extensibility model</i> defining the concepts of SOAP features and SOAP modules<sup about="#mwt65" class="mw-ref reference" id="cite_ref-auto_16-1" rel="dc:references" typeof="mw:Extension/ref" data-mw='{"name":"ref","attrs":{"name":"auto"}}'><a href="#cite_note-auto-16" id="mw0A"><span class="mw-reflink-text" id="mw0Q"><span class="cite-bracket" id="mw0g">[</span>15<span class="cite-bracket" id="mw0w">]</span></span></a></sup></li>
<li id="mw1A">The <i id="mw1Q">SOAP underlying protocol binding</i> framework describing the rules for defining a binding to an underlying protocol that can be used for exchanging SOAP messages between SOAP nodes<sup about="#mwt66" class="mw-ref reference" id="cite_ref-auto_16-2" rel="dc:references" typeof="mw:Extension/ref" data-mw='{"name":"ref","attrs":{"name":"auto"}}'><a href="#cite_note-auto-16" id="mw1g"><span class="mw-reflink-text" id="mw1w"><span class="cite-bracket" id="mw2A">[</span>15<span class="cite-bracket" id="mw2Q">]</span></span></a></sup></li>
<li id="mw2g">The <i id="mw2w">SOAP message construct</i> defining the structure of a SOAP message<sup about="#mwt67" class="mw-ref reference" id="cite_ref-auto_16-3" rel="dc:references" typeof="mw:Extension/ref" data-mw='{"name":"ref","attrs":{"name":"auto"}}'><a href="#cite_note-auto-16" id="mw3A"><span class="mw-reflink-text" id="mw3Q"><span class="cite-bracket" id="mw3g">[</span>15<span class="cite-bracket" id="mw3w">]</span></span></a></sup></li></ul>

</section><section data-mw-section-id="9" id="mw-A" aria-labelledby="Transport_methods"><div class="mw-heading mw-heading2"><h2 id="Transport_methods">Transport methods</h2><span class="mw-editsection"><span class="mw-editsection-bracket">[</span><a href="/w/index.php?title=SOAP&amp;action=edit&amp;section=9" title="Edit section: Transport methods"><span>edit</span></a><span class="mw-editsection-bracket">]</span></span></div>
<p id="mw-Q">Both <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/SMTP" title="SMTP" class="mw-redirect" id="mw-g">SMTP</a> and <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/HTTP" title="HTTP" id="mw-w">HTTP</a> are valid application layer protocols used as transport for SOAP, but HTTP has gained wider acceptance as it works well with today's internet infrastructure; specifically, HTTP works well with network <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Firewall_(networking)" title="Firewall (networking)" class="mw-redirect" id="mw_A">firewalls</a>. SOAP may also be used over <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/HTTPS" title="HTTPS" id="mw_Q">HTTPS</a> (which is the same protocol as HTTP at the application level, but uses an <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Transport_Layer_Security" title="Transport Layer Security" id="mw_g">encrypted transport protocol</a> underneath) with either simple or mutual authentication; this is the advocated <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/WS-I" title="WS-I" class="mw-redirect" id="mw_w">WS-I</a> method to provide web service security as stated in the <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/WS-I_Basic_Profile" title="WS-I Basic Profile" id="mwAQA">WS-I Basic Profile</a> 1.1.</p>

<p id="mwAQE">This is a major advantage over other distributed protocols like <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/General_Inter-ORB_Protocol" title="General Inter-ORB Protocol" id="mwAQI">GIOP/IIOP</a> or <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Distributed_Component_Object_Model" title="Distributed Component Object Model" id="mwAQM">DCOM</a>, which are normally filtered by firewalls. SOAP over <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/AMQP" title="AMQP" class="mw-redirect" id="mwAQQ">AMQP</a> is yet another possibility that some implementations support.  SOAP also has an advantage over <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Distributed_Component_Object_Model" title="Distributed Component Object Model" id="mwAQU">DCOM</a> that it is unaffected by security rights configured on the machines that require knowledge of both transmitting and receiving nodes. This lets SOAP be loosely coupled in a way that is not possible with <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Distributed_Component_Object_Model" title="Distributed Component Object Model" id="mwAQY">DCOM</a>.  There is also the <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/SOAP-over-UDP" title="SOAP-over-UDP" id="mwAQc">SOAP-over-UDP</a> <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/OASIS_(organization)" title="OASIS (organization)" class="mw-redirect" id="mwAQg">OASIS</a> standard.</p>

</section><section data-mw-section-id="10" id="mwAQk" aria-labelledby="Message_format"><div class="mw-heading mw-heading2"><h2 id="Message_format">Message format</h2><span class="mw-editsection"><span class="mw-editsection-bracket">[</span><a href="/w/index.php?title=SOAP&amp;action=edit&amp;section=10" title="Edit section: Message format"><span>edit</span></a><span class="mw-editsection-bracket">]</span></span></div>
<p id="mwAQo"><a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/XML_Information_Set" title="XML Information Set" id="mwAQs">XML Information Set</a> was chosen as the standard message format because of its widespread use by major corporations and <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Open-source_model" title="Open-source model" class="mw-redirect" id="mwAQw">open source</a> development efforts. Typically, XML Information Set is <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Serialization" title="Serialization" id="mwAQ0">serialized</a> as <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/XML" title="XML" id="mwAQ4">XML</a>. A wide variety of freely available <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Software_development_tool" title="Software development tool" class="mw-redirect" id="mwAQ8">tools</a> significantly eases the transition to a SOAP-based implementation. The somewhat lengthy <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Syntax" title="Syntax" id="mwARA">syntax</a> of <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/XML" title="XML" id="mwARE">XML</a> can be both a benefit and a drawback. While it facilitates error detection and avoids interoperability problems such as byte-order (<a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Endianness" title="Endianness" id="mwARI">endianness</a>), it can slow processing speed and can be cumbersome. For example, <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/CORBA" title="CORBA" class="mw-redirect" id="mwARM">CORBA</a>, <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/General_Inter-ORB_Protocol" title="General Inter-ORB Protocol" id="mwARQ">GIOP</a>, <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Internet_Communications_Engine" title="Internet Communications Engine" id="mwARU">ICE</a>, and <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Distributed_Component_Object_Model" title="Distributed Component Object Model" id="mwARY">DCOM</a><!--EDIFACT too :P--> use much shorter, binary message formats. On the other hand, hardware appliances are available to accelerate processing of <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/XML" title="XML" id="mwARc">XML</a> messages.<sup about="#mwt70" class="mw-ref reference" id="cite_ref-17" rel="dc:references" typeof="mw:Extension/ref" data-mw='{"name":"ref","attrs":{},"body":{"id":"mw-reference-text-cite_note-17"}}'><a href="#cite_note-17" id="mwARg"><span class="mw-reflink-text" id="mwARk"><span class="cite-bracket" id="mwARo">[</span>16<span class="cite-bracket" id="mwARs">]</span></span></a></sup><sup about="#mwt73" class="mw-ref reference" id="cite_ref-18" rel="dc:references" typeof="mw:Extension/ref" data-mw='{"name":"ref","attrs":{},"body":{"id":"mw-reference-text-cite_note-18"}}'><a href="#cite_note-18" id="mwARw"><span class="mw-reflink-text" id="mwAR0"><span class="cite-bracket" id="mwAR4">[</span>17<span class="cite-bracket" id="mwAR8">]</span></span></a></sup> <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Binary_XML" title="Binary XML" id="mwASA">Binary XML</a> is also being explored as a means for streamlining the throughput requirements of XML.
XML messages by their self-documenting nature usually have more 'overhead' (e.g., headers, nested tags, delimiters) than actual data in contrast to earlier protocols where the overhead was usually a relatively small percentage of the overall message.</p>

<p id="mwASE">In financial messaging SOAP was found to result in a 2<span typeof="mw:Entity" id="mwASI">–</span>4 times larger message than previous protocols <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Financial_Information_eXchange" title="Financial Information eXchange" id="mwASM">FIX</a> (Financial Information Exchange) and <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Common_Data_Representation" title="Common Data Representation" id="mwASQ">CDR</a> (Common Data Representation).<sup about="#mwt76" class="mw-ref reference" id="cite_ref-19" rel="dc:references" typeof="mw:Extension/ref" data-mw='{"name":"ref","attrs":{},"body":{"id":"mw-reference-text-cite_note-19"}}'><a href="#cite_note-19" id="mwASU"><span class="mw-reflink-text" id="mwASY"><span class="cite-bracket" id="mwASc">[</span>18<span class="cite-bracket" id="mwASg">]</span></span></a></sup></p>

<p id="mwASk">XML Information Set does not have to be serialized in XML. For instance, CSV and <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/JSON" title="JSON" id="mwASo">JSON</a> XML-infoset representations exist. There is also no need to specify a generic transformation framework. The concept of SOAP bindings allows for specific bindings for a specific application. The drawback is that both the senders and receivers have to support this newly defined binding.</p>

<section data-mw-section-id="13" id="mwAVw" aria-labelledby="Advantages"><div class="mw-heading mw-heading3"><h3 id="Advantages">Advantages</h3><span class="mw-editsection"><span class="mw-editsection-bracket">[</span><a href="/w/index.php?title=SOAP&amp;action=edit&amp;section=13" title="Edit section: Advantages"><span>edit</span></a><span class="mw-editsection-bracket">]</span></span></div>
<ul id="mwAV0"><li id="mwAV4">SOAP's neutrality characteristic explicitly makes it suitable for use with any transport protocol. Implementations often use HTTP as a transport protocol, but other popular transport protocols can be used. For example, SOAP can also be used over SMTP,<sup about="#mwt82" class="mw-ref reference" id="cite_ref-20" rel="dc:references" typeof="mw:Extension/ref" data-mw='{"name":"ref","attrs":{},"body":{"id":"mw-reference-text-cite_note-20"}}'><a href="#cite_note-20" id="mwAV8"><span class="mw-reflink-text" id="mwAWA"><span class="cite-bracket" id="mwAWE">[</span>19<span class="cite-bracket" id="mwAWI">]</span></span></a></sup> <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Java_Message_Service" title="Java Message Service" class="mw-redirect" id="mwAWM">JMS</a><sup about="#mwt85" class="mw-ref reference" id="cite_ref-21" rel="dc:references" typeof="mw:Extension/ref" data-mw='{"name":"ref","attrs":{},"body":{"id":"mw-reference-text-cite_note-21"}}'><a href="#cite_note-21" id="mwAWQ"><span class="mw-reflink-text" id="mwAWU"><span class="cite-bracket" id="mwAWY">[</span>20<span class="cite-bracket" id="mwAWc">]</span></span></a></sup><sup about="#mwt88" class="mw-ref reference" id="cite_ref-22" rel="dc:references" typeof="mw:Extension/ref" data-mw='{"name":"ref","attrs":{},"body":{"id":"mw-reference-text-cite_note-22"}}'><a href="#cite_note-22" id="mwAWg"><span class="mw-reflink-text" id="mwAWk"><span class="cite-bracket" id="mwAWo">[</span>21<span class="cite-bracket" id="mwAWs">]</span></span></a></sup> and <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Message_queue" title="Message queue" id="mwAWw">message queues</a>.</li>
<li id="mwAW0">SOAP, when combined with HTTP post/response exchanges, tunnels easily through existing firewalls and proxies, and consequently doesn't require modifying the widespread computing and communication infrastructures that exist for processing HTTP post/response exchanges.</li>
<li id="mwAW4">SOAP has available to it all the facilities of XML, including easy internationalization and extensibility with XML Namespaces.</li></ul>

</section><section data-mw-section-id="14" id="mwAW8" aria-labelledby="Disadvantages"><div class="mw-heading mw-heading3"><h3 id="Disadvantages">Disadvantages</h3><span class="mw-editsection"><span class="mw-editsection-bracket">[</span><a href="/w/index.php?title=SOAP&amp;action=edit&amp;section=14" title="Edit section: Disadvantages"><span>edit</span></a><span class="mw-editsection-bracket">]</span></span></div>
<ul id="mwAXA"><li id="mwAXE">When using standard implementation and the default SOAP/HTTP binding, the XML infoset is serialized as XML. To improve performance for the special case of XML with embedded binary objects, the <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Message_Transmission_Optimization_Mechanism" title="Message Transmission Optimization Mechanism" id="mwAXI">Message Transmission Optimization Mechanism</a> was introduced.</li>
<li id="mwAXM">When relying on HTTP as a transport protocol and not using <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/WS-Addressing" title="WS-Addressing" id="mwAXQ">Web Services Addressing</a> or an <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Enterprise_Service_Bus" title="Enterprise Service Bus" class="mw-redirect" id="mwAXU">Enterprise Service Bus</a>, the roles of the interacting parties are fixed. Only one party (the client) can use the services of the other.</li>
<li id="mwAXY">SOAP is less "simple" than the name would suggest. The verbosity of the protocol, low parsing speed of XML, and lack of a standardized interaction model led to the dominance of services using the <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/HTTP" title="HTTP" id="mwAXc">HTTP</a> protocol more directly. See, for example, <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Representational_state_transfer" title="Representational state transfer" class="mw-redirect" id="mwAXg">REST</a>.</li>
<li id="mwAXk">Being protocol-agnostic, SOAP is unable to take advantage of protocol-specific features and optimizations such as <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Representational_state_transfer#Uniform_interface" title="Representational state transfer" class="mw-redirect" id="mwAXo">REST's Uniform Interface</a> or <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/Web_cache" title="Web cache" id="mwAXs">caching</a> – instead having to reimplement them (as with <a rel="mw:WikiLink" href="https://en.wikipedia.org/wiki/WS-Addressing" title="WS-Addressing" id="mwAXw">WS-Addressing</a>).</li></ul>
