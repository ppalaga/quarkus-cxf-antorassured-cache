<h1 class="page">Testing Antora sites</h1>
<div id="preamble">
<div class="sectionbody">
<div class="paragraph">
<p>This project provides utilities and guidelines for testing Antora documentation sites.</p>
</div>
<div class="paragraph">
<p>Quarkiverse projects usually host their Antora documentation in a dedicated <code>docs</code> Maven module.
After adding the <code>quarkus-antora</code> dependency, you can not only
<a href="index.html#dev-mode" class="xref page">life-edit the site in Quarkus dev mode</a> but also</p>
</div>
<div class="ulist">
<ul>
<li>
<p>Test that Antora is able to generate the site from your AsciiDoc sources</p>
</li>
<li>
<p>Ensure that all external links are valid.</p>
</li>
</ul>
</div>
</div>
</div>
<div class="sect1">
<h2 id="_basic_quarkustest"><a class="anchor" href="#_basic_quarkustest"></a>Basic <code>@QuarkusTest</code></h2>
<div class="sectionbody">
<div class="paragraph">
<p>The way we test the site generation is not much different from
<a href="https://quarkus.io/guides/getting-started-testing">testing any other Quarkus application</a>.</p>
</div>
<div class="paragraph">
<p>First, you need to add the necessary dependencies</p>
</div>
<div class="listingblock">
<div class="content">
<pre class="highlightjs highlight"><code class="language-xml hljs" data-lang="xml">        &lt;dependency&gt;
            &lt;groupId&gt;io.quarkiverse.antora&lt;/groupId&gt;
            &lt;artifactId&gt;quarkus-antora&lt;/artifactId&gt;
        &lt;/dependency&gt;

        &lt;!-- Test dependencies --&gt;
        &lt;dependency&gt;
            &lt;groupId&gt;io.quarkus&lt;/groupId&gt;
            &lt;artifactId&gt;quarkus-junit&lt;/artifactId&gt;
            &lt;scope&gt;test&lt;/scope&gt;
        &lt;/dependency&gt;
        &lt;dependency&gt;
            &lt;groupId&gt;io.rest-assured&lt;/groupId&gt;
            &lt;artifactId&gt;rest-assured&lt;/artifactId&gt;
            &lt;scope&gt;test&lt;/scope&gt;
        &lt;/dependency&gt;
        &lt;dependency&gt;
            &lt;groupId&gt;org.assertj&lt;/groupId&gt;
            &lt;artifactId&gt;assertj-core&lt;/artifactId&gt;
            &lt;scope&gt;test&lt;/scope&gt;
        &lt;/dependency&gt;</code></pre>
</div>
</div>
<div class="paragraph">
<p>Then you can add a basic <code>@QuarkusTest</code> as follows:</p>
</div>
<div class="listingblock">
<div class="content">
<pre class="highlightjs highlight"><code class="language-java hljs" data-lang="java">import org.hamcrest.CoreMatchers;
import org.junit.jupiter.api.Test;

import io.quarkiverse.antorassured.AntorAssured;
import io.quarkus.test.junit.QuarkusTest;
import io.restassured.RestAssured;
import io.restassured.http.ContentType;

@QuarkusTest /* the @QuarkusTest annotation lets Quarkus build and start the Antora site on http://localhost:8081/ */
public class AntoraSiteTest {

    @Test
    public void getIndex() {

        /*
         * If the site was built successfully,
         * we can get the index page and check that
         * it contains some expected content
         */
        RestAssured
                .given()
                .contentType(ContentType.HTML)
                .get("/quarkus-antora/dev/index.html")
                .then()
                .statusCode(200)
                .body(CoreMatchers.containsString("&lt;h1 class=\"page\"&gt;Quarkus Antora&lt;/h1&gt;"));
    }
    ...
}</code></pre>
</div>
</div>
<div class="admonitionblock tip">
<table>
<tr>
<td class="icon">
<i class="fa icon-tip" title="Tip"></i>
</td>
<td class="content">
<div class="paragraph">
<p>The sample code snippets used in this section come from the
<a href="https://github.com/quarkiverse/quarkus-antora/tree/main/docs"><code>docs</code> module</a> of Quarkus Antora</p>
</div>
</td>
</tr>
</table>
</div>
</div>
</div>
<div class="sect1">
<h2 id="antorassured"><a class="anchor" href="#antorassured"></a>Detect dead links with <code>AntorAssured</code></h2>
<div class="sectionbody">
<div class="paragraph">
<p>Antora takes care for validating internal cross-references but it does not help much with ensuring
that external links point to existing resources.
Page fragments (the part starting with <code>#</code> in <code>page.html#anchor</code>) are not validated by Antora too.</p>
</div>
<div class="paragraph">
<p>That&#8217;s where the <code>io.quarkiverse.antorassured.AntorAssured</code> class provided by Quarkus Antora may come in handy.</p>
</div>
<div class="paragraph">
<p>To use it, you need to add the following dependency:</p>
</div>
<div class="listingblock">
<div class="content">
<pre class="highlightjs highlight"><code class="language-xml hljs" data-lang="xml">        &lt;dependency&gt;
            &lt;groupId&gt;io.quarkiverse.antora&lt;/groupId&gt;
            &lt;artifactId&gt;quarkus-antorassured&lt;/artifactId&gt;
            &lt;scope&gt;test&lt;/scope&gt;
        &lt;/dependency&gt;</code></pre>
</div>
</div>
<div class="paragraph">
<p>Then you can use it in a test as follows:</p>
</div>
<div class="listingblock">
<div class="content">
<pre class="highlightjs highlight"><code class="language-java hljs" data-lang="java">    @Test
    public void validateLinks() {

        AntorAssured
                .links()
                .excludeResolved(
                        /* Broken links available in test-page.adoc for the sake of testing */
                        "https://salkjasjhashgajhhsahgahjas.com",
                        "https://quarkus.io/fake-page",
                        "https://quarkus.io/guides/building-native-image#fake-fragment",
                        "http://localhost:8083/retry-me",
                        /* When running this test, the port is 8081, so the following link is not expected to work */
                        "http://localhost:8080/quarkus-antora/dev/index.html")
                .excludeEditThisPage()
                /*
                 * Retry once (default) in case of HTTP status 301, 429, 500, 501, 502, 503
                 * or 504, after 10 seconds or what the Retry-After HTTP header prescribes,
                 * but at most 120 seconds
                 */
                .retryAttempts(1)
                .validate()
                .assertValid();
    }</code></pre>
</div>
</div>
<div class="paragraph">
<p>In the test, we instruct the link validator to ignore some remote URIs, that we intentionally placed into <code>test-page.adoc</code>
for the sake of testing <code>AntoraAssured</code> itself.</p>
</div>
<div class="paragraph">
<p>If you would like to see the dead link detection in action, just remove the whole <code>excludeResolved(&#8230;&#8203;)</code> method invocation.
After that, you should see the test fail with a report like the following:</p>
</div>
<div class="listingblock">
<div class="content">
<pre class="highlightjs highlight"><code class="language-text hljs" data-lang="text">[ERROR]   AntoraSiteTest.validateLinks:48
 - /home/user/projects/quarkus-antora/docs/modules/ROOT/pages/index.adoc:59
     - http://localhost:8080/quarkus-antora/dev/index.html -&gt; http://localhost:8080/quarkus-antora/dev/index.html
         - Unable to connect: Connection refused
 - /home/user/projects/quarkus-antora/docs/modules/ROOT/pages/test-page.adoc:15
     - https://quarkus.io/fake-page -&gt; https://quarkus.io/fake-page
         - 404
 - /home/user/projects/quarkus-antora/docs/modules/ROOT/pages/test-page.adoc:14
     - https://salkjasjhashgajhhsahgahjas.com -&gt; https://salkjasjhashgajhhsahgahjas.com
         - Unknown host salkjasjhashgajhhsahgahjas.com
 - /home/user/projects/quarkus-antora/docs/modules/ROOT/pages/test-page.adoc:16
     - https://quarkus.io/guides/building-native-image#fake-fragment -&gt; https://quarkus.io/guides/building-native-image#fake-fragment
         - Could not find #fake-fragment</code></pre>
</div>
</div>
<div class="sect2">
<h3 id="persistent-cache"><a class="anchor" href="#persistent-cache"></a>Persistent cache of remote pages</h3>
<div class="paragraph">
<p>Link validation typically runs with every build, while most remote pages change rarely.
Some remote servers do not tolerate being accessed that often and respond with <code>429 Too Many Requests</code>.</p>
</div>
<div class="paragraph">
<p>Therefore, since Quarkus Antora 4.0.0, <code>AntorAssured</code> stores the remote pages it has fetched in the local file system
and reuses them in subsequent runs.
The cache is enabled by default.</p>
</div>
<table class="tableblock frame-all grid-all stretch">
<colgroup>
<col style="width: 33.3333%;">
<col style="width: 66.6667%;">
</colgroup>
<thead>
<tr>
<th class="tableblock halign-left valign-top">Setting</th>
<th class="tableblock halign-left valign-top">Default</th>
</tr>
</thead>
<tbody>
<tr>
<td class="tableblock halign-left valign-top"><p class="tableblock">Cache directory</p></td>
<td class="tableblock halign-left valign-top"><p class="tableblock"><code>~/.cache/antorassured/pages</code>, where <code>~</code> is the value of the <code>user.home</code> system property</p></td>
</tr>
<tr>
<td class="tableblock halign-left valign-top"><p class="tableblock">Expiration: pages fetched longer ago are fetched again</p></td>
<td class="tableblock halign-left valign-top"><p class="tableblock">36 hours</p></td>
</tr>
<tr>
<td class="tableblock halign-left valign-top"><p class="tableblock">Garbage collection age: pages fetched longer ago are deleted from the cache directory</p></td>
<td class="tableblock halign-left valign-top"><p class="tableblock">180 days</p></td>
</tr>
</tbody>
</table>
<div class="paragraph">
<p>The cache works as follows:</p>
</div>
<div class="ulist">
<ul>
<li>
<p>Before a page is fetched, the cache directory is consulted.
If the page was stored there within the expiration period, it is not requested from the remote server.
The stored page is used instead, also for validating the fragments of the links.</p>
</li>
<li>
<p>A cached page does not count against any <code>RateLimit</code> and it is never delayed by it.
It is still counted by policies such as <code>AggregatePolicy.countAtLeast(200, n)</code>.</p>
</li>
<li>
<p>Only responses having a <code>2xx</code> status are stored.
Other responses, such as <code>404</code>, <code>429</code> or <code>503</code>, timeouts and connection failures are never stored,
so broken links are checked against the remote server with each run.</p>
</li>
<li>
<p>The site under test is never stored.
By default, this applies to all URIs whose host is <code>localhost</code> or a loopback IP address, such as <code>127.0.0.1</code>.
<code>LinkStream.validate()</code> (without parameters) in addition excludes all URIs under the base URI of the site under test,
which is important if you set <code>quarkus.http.test-host</code> to some other host name.</p>
</li>
<li>
<p>URIs containing credentials, such as <code>https://user:password@example.com/</code>, are never stored.</p>
</li>
<li>
<p>Pages requested with different <code>Accept</code> headers are stored separately.
Other request headers are not taken into account.</p>
</li>
<li>
<p>The cache directory can be used by several builds at the same time.</p>
</li>
</ul>
</div>
<div class="sect3">
<h4 id="_stale_pages"><a class="anchor" href="#_stale_pages"></a>Stale pages</h4>
<div class="paragraph">
<p>The cache makes the validation faster and less demanding for the remote servers at the cost of working with pages
that may be up to 36 hours old (or whatever expiration you set):</p>
</div>
<div class="ulist">
<ul>
<li>
<p>A link to a page that was removed from the remote server in the meantime is still reported as valid.</p>
</li>
<li>
<p>A link to a fragment that was added to the remote page in the meantime is still reported as invalid.</p>
</li>
</ul>
</div>
<div class="paragraph">
<p>Both issues go away after the cached page expires.
If you do not want to wait, delete the cache directory or only the directory of the given page.
The path of the directory is derived from the URI of the page as follows:
<code>&lt;cache directory&gt;/&lt;reversed host name&gt;/&lt;scheme&gt;/&lt;port&gt;/&lt;accept header&gt;/&lt;path&gt;</code>.
For example, <code>https://quarkus.io/guides/building-native-image</code> is stored in
<code>~/.cache/antorassured/pages/io/quarkus/https/443/no-accept/guides/building-native-image</code>.
Characters that are not allowed in file names on some operating system are replaced by underscores.</p>
</div>
<div class="paragraph">
<p>Deleting the files is always safe.
The validation never fails because of a missing or broken content of the cache directory.</p>
</div>
</div>
<div class="sect3">
<h4 id="_garbage_collection"><a class="anchor" href="#_garbage_collection"></a>Garbage collection</h4>
<div class="paragraph">
<p>At the end of each validation that has used the cache, the pages fetched more than 180 days ago are deleted from the cache
directory, together with the directories that became empty.
These are typically pages that are not linked from your documentation anymore.
Files not created by <code>AntorAssured</code> are never deleted.</p>
</div>
</div>
<div class="sect3">
<h4 id="persistent-cache-ci"><a class="anchor" href="#persistent-cache-ci"></a>Using the cache on CI</h4>
<div class="paragraph">
<p>The cache is useful on CI only if the cache directory is restored before the build and saved after it.
The directory to save and restore is <code>~/.cache/antorassured/pages</code>, unless you have configured another one.
It can be copied to another machine, even to one running a different operating system.</p>
</div>
<div class="admonitionblock note">
<table>
<tr>
<td class="icon">
<i class="fa icon-note" title="Note"></i>
</td>
<td class="content">
<div class="paragraph">
<p>The pages are stored as they were received, without any encryption.
Keep that in mind if you validate links to private resources, for example using <code>LinkGroup.bearerToken(String)</code> or
<code>LinkGroup.basicAuth(String, String)</code>, and you share the cache directory with others.
The tokens and passwords themselves are never stored.</p>
</div>
</td>
</tr>
</table>
</div>
</div>
<div class="sect3">
<h4 id="_configuring_the_cache"><a class="anchor" href="#_configuring_the_cache"></a>Configuring the cache</h4>
<div class="paragraph">
<p>The cache can be configured only by passing a custom <code>LinkValidatorImpl</code> to <code>LinkStream.validate(LinkValidator)</code>:</p>
</div>
<div class="listingblock">
<div class="content">
<pre class="highlightjs highlight"><code class="language-java hljs" data-lang="java">AntorAssured
        .links()
        .excludeEditThisPage()
        .validate(
                new LinkValidatorImpl(
                        /* Where the pages are stored */
                        Path.of("target/antorassured-cache"),
                        /* Pages fetched more than 12 hours ago are fetched again */
                        Duration.ofHours(12),
                        /* Pages fetched more than 30 days ago are deleted from the cache directory */
                        Duration.ofDays(30),
                        LinkValidatorImpl.DEFAULT_CACHE_LOCK_RETRY_DELAY,
                        LinkValidatorImpl.DEFAULT_CACHE_LOCK_RETRIES,
                        /* Which URIs may be cached: anything but the site under test running on localhost */
                        LinkValidatorImpl.notLoopback(),
                        Clock.systemUTC()))
        .assertValid();</code></pre>
</div>
</div>
<div class="admonitionblock warning">
<table>
<tr>
<td class="icon">
<i class="fa icon-warning" title="Warning"></i>
</td>
<td class="content">
<div class="paragraph">
<p>A <code>LinkValidatorImpl</code> you create yourself does not know the base URI of the site under test.
If your site under test is not served from <code>localhost</code>,
make sure that the predicate passed to the constructor returns <code>false</code> for its URIs.
Otherwise, the internal links would be validated against a previous build of your site.</p>
</div>
</td>
</tr>
</table>
</div>
<div class="paragraph">
<p>There is no dedicated option for disabling the cache.
Pass a predicate returning <code>false</code> for every URI instead:</p>
</div>
<div class="listingblock">
<div class="content">
<pre class="highlightjs highlight"><code class="language-java hljs" data-lang="java">AntorAssured
        .links()
        .excludeEditThisPage()
        .validate(
                new LinkValidatorImpl(
                        LinkValidatorImpl.defaultCacheDirectory(),
                        LinkValidatorImpl.DEFAULT_CACHE_EXPIRATION,
                        LinkValidatorImpl.DEFAULT_CACHE_GC_AGE,
                        LinkValidatorImpl.DEFAULT_CACHE_LOCK_RETRY_DELAY,
                        LinkValidatorImpl.DEFAULT_CACHE_LOCK_RETRIES,
                        /* No URI may be cached */
                        uri -&gt; false,
                        Clock.systemUTC()))
        .assertValid();</code></pre>
</div>
</div>
</div>
</div>
